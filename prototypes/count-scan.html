Design decisions & open questions — count-scan.html

Decisions

  • The search+scan field is pinned at the bottom of the screen, not the top the reference/design-system component shows it at by default. CLAUDE.md's "primary actions sit in the lower half" rule outranks the reference's placement for this specific screen — scanning is the single most-repeated action in the whole app, so it gets the thumb-reachable position. The bottom tab bar is dropped entirely on this screen since an active count is a focused session, not a place to jump to Catalog/Reports mid-scan.
  • Invariant 3 is made visible, not just correct. "Simulate scan: duplicate" pulses the existing Tito's row, bumps its quantity, and shows an ephemeral "already on this count — updated" badge, rather than silently updating a number nobody notices changed. This was called out as the #1 source of user distrust, so it gets its own explicit confirmation rather than folding into the ordinary optimistic-insert flash.
  • The ambient "N pending / all synced" pill stays a neutral muted color always — it is deliberately not colored amber/green, because docs/design-system.md §3 reserves green/amber/red exclusively for stock and count-session status, and sync/connectivity state is neither. The one-off "just saved" flash on a row briefly uses success-green, which is defensible because it's confirming a completed write (the same "step completed" meaning §3 already sanctions), not decorating a persistent state.
  • Role toggle demonstrates the §8 contract literally: switching to manager/staff removes the money `<span>` node from the DOM and collapses the grid to one column via JS, rather than hiding it with CSS — mirroring "the field is undefined, not styled away."
  • Two lines (Tanqueray, Coors Light keg) link out to count-fill-tenths.html, showing how the scan screen hands off to the tenths editor for anything open/tapped.
  • Category glyphs are two-letter monograms (SP/KG) per divergence #4 — no product photography, no file storage in the MVP.
  • Location is locked per leg (AGENTS.md, ui-spec-mobile.md §5), not switchable from this screen. The location pill is a non-interactive status display — no chevron, no aria-haspopup, nothing implying a tap opens a switcher — because a wrong active location fails silently: every scan still lands on a real line, the count total stays correct, and only the distribution is wrong until a reorder list is nonsense weeks later. The only way to record into a different location without changing the active leg is the separate, deliberately heavier "Count a stray bottle elsewhere" control next to the pill, which reveals an inline note rather than opening a sheet or navigating away. This earlier prototype showed a free-switch location dropdown; that part was superseded and is not carried forward.

Open questions for the owner

  • Should the "already counted — updated" confirmation require an explicit tap to dismiss for the first few times a new staff member uses the app (a teaching moment), rather than always auto-fading after 2 seconds?
