Design decisions & open questions — scan-to-enroll.html

Fields kept, and why

  • Barcode — read-only display of the value the scan already produced. Zero interaction cost, which is the whole point of scan-to-enroll.
  • Name — the one field that must be typed. Autofocused so the keyboard is up and the cursor is ready the instant the screen appears.
  • Category — one-tap chip group over a dropdown or free text, because the catalog's real category set is small and closed (spirits/beer/wine/liqueur/draft/N-A per docs/handlebar-catalog.xlsx) — a chip is faster than opening a picker.
  • Size — chip set that changes with category and pre-selects the most common value for that category (750ml for spirits, half barrel for draft, etc.), so the fast path is zero taps if the default is right.
  • Case size — prefilled from the category default, editable; hidden entirely for Draft Keg since kegs aren't cased.
  • "This barcode is for a case" checkbox — defaults unchecked (each), since a first scan-to-enroll is almost always off a single bottle/can, not a case carton.
  • Cost per unit — owner-only, and the field is removed from the DOM entirely for manager/staff rather than shown-then-silently-dropped, even though `createProductAction` would strip it either way — showing a field that quietly does nothing is its own small lie.

Fields cut, and why

  • Vendor — not needed to keep counting; assigning a vendor is a back-office task, not a floor task, and the schema's `vendorId` is nullable.
  • Subcategory, waste factor, shelf life, par level — all optional/nullable in the schema, all deferred to the back office. None of them block a count from proceeding.
  • Barcode format/symbology — the `BarcodeDetector` result already reports this; it is never something a human types.
  • The reference's 5-step wizard — discarded outright per design-reference.md divergence #2. This is one screen, full stop.

Open questions for the owner

  • Is "guess the category from the barcode's GS1 prefix" worth building later, to pre-select a category chip instead of always defaulting to Spirits?
  • Wine in the real catalog is currently varietal-level (Merlot, Chardonnay) without a producer (per CLAUDE.md's open question #1-adjacent note) — should scan-to-enroll for wine ask for a producer name up front, or is that also a back-office cleanup task?
