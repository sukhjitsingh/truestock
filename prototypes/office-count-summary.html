Design decisions

  • excludedLineCount/pricedLineCount are NOT role-gated in lib/domain/reports.ts — only totalValue and each line's extendedValue are. So the "7 of 49 lines unpriced" banner and the "42 of 49 priced" stat appear identically for both roles; only the dollar figures swap in and out. The manager headline reframes this as a data-completeness signal ("which products still need a cost"), which is legitimately useful without leaking a dollar amount.
  • The excluded-lines banner sits above the headline number, in warning amber, and is never folded into the total — directly implementing the brief's "never $0, never folded in" requirement. Wine's category row reads "Unpriced" rather than "$0" for the same reason.
  • Comparison to the previous count is dollar-based for owner (+6.5%) and unit-based for manager (+58 units) — same underlying comparison, role-appropriate unit of measure.
  • By-location breakdown includes the tap lines as their own row (draft kegs record against Location rows per CLAUDE.md's "tap lines can be modeled as Locations, no schema change needed") rather than lumping draft in with a physical bar location.
  • Status pill "Closed" uses success green — this is a count-session status (draft→in_progress→submitted→reviewed→closed), an approved use per §3, not a stock reading.

Open questions

  • Category/location breakdown isn't computed anywhere yet. countSummary() returns a flat lines[] array with category and locationId per line, but no aggregated-by-category or aggregated-by-location shape. This screen assumes that grouping happens client-side (or in a new domain function) — worth confirming before building it for real, especially since the owner/manager value-sum would need the same role gate applied to the aggregate, not just the per-line figures.
  • "Comparison to previous count" has no backing data or function at all — CountSummary is single-count. Showing a trend requires fetching two summaries and diffing them; not decided whether that diff happens in a new server action or in this page's own data-fetching.
  • Locations aren't in the read domain functions shown (only listLocations() in catalog.ts, unfiltered by count). Location names above are invented for the mockup — the real seed's actual location list (from db/README.md/locations.csv, not read for this task) may differ.
